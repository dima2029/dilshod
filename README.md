# Склад Skechers

Веб-приложение для учёта товаров на складе + Telegram-бот + интеграция остатков из **МойСклад**.
Всё работает **внутри Railway**: приложение (сайт + бот) и база данных **Postgres** — в одном проекте. Внешние сервисы не нужны.

- **Сайт** — таблица товаров, добавление/поиск/редактирование, экспорт в Excel. Открывается по ссылке (без пароля), для сотрудников — кнопка «🌐 Войти в сайт» прямо в Telegram-боте.
- **Telegram-бот** — управление товарами и уведомления прямо в чате.
- **МойСклад** — команда `/ostatki` показывает реальные остатки по артикулу.

---

## Как это устроено

```
   ┌──────────────────────── Railway (один проект) ────────────────────────┐
   │                                                                        │
   │   Браузер  ───►  Express: сайт + /api/items ──►  Postgres (Railway)    │
   │                        │                          места на складе      │
   │   Telegram ───►  Бот (polling): /list /find /add /del /export /ostatki │
   │                        │           └── /ostatki ─► МойСклад (остатки)   │
   │                        └── уведомления об изменениях на сайте ─► чат    │
   │                                                                        │
   └────────────────────────────────────────────────────────────────────────┘
```

Данные хранятся в **Postgres** (Railway), таблица `items` создаётся автоматически при первом запуске:

| поле | смысл |
|------|-------|
| `article` | артикул (ключ, в верхнем регистре) |
| `name` | название |
| `warehouse`, `floor`, `row`, `cell` | склад, этаж, ряд, ячейка |
| `created_at` | дата добавления |

## Переменные окружения

Задаются в **Railway → вкладка Variables**. В код секреты не пишутся.

| Переменная | Обязательна | Описание |
|------------|:-----------:|----------|
| `DATABASE_URL` | да | подключение к Postgres — **Railway подставляет автоматически**, если сослаться на базу (см. ниже) |
| `TELEGRAM_BOT_TOKEN` | для бота | токен бота от [@BotFather](https://t.me/BotFather) |
| `TELEGRAM_CHAT_ID` | для уведомлений | чат, куда слать уведомления; также становится админом бота |
| `TELEGRAM_ADMINS` | нет | список chat_id через запятую, кому разрешены команды (по умолчанию — только `TELEGRAM_CHAT_ID`) |
| `MOYSKLAD_TOKEN` | для остатков | Bearer-токен МойСклад (**или** пара логин/пароль ниже) |
| `MOYSKLAD_LOGIN` | альтернатива токену | логин МойСклад |
| `MOYSKLAD_PASSWORD` | альтернатива токену | пароль МойСклад |
| `MOYSKLAD_MATCH_FIELD` | нет | по какому полю искать товар: `article` (по умолчанию) или `code` |
| `SITE_URL` | нет | адрес сайта для кнопки «🌐 Войти в сайт» в боте — **Railway подставляет автоматически** через `RAILWAY_PUBLIC_DOMAIN`, задавай вручную только если домен свой |
| `PGSSL` | нет | `true`, если подключаешься к Postgres по внешнему URL (для внутреннего Railway не нужно) |
| `PORT` | нет | Railway подставляет автоматически |

> Если какой-то блок не настроен — он просто отключается, остальное работает.
> Нет `TELEGRAM_BOT_TOKEN` → бот выключен. Нет данных МойСклад → `/ostatki` вежливо сообщит об этом.

## Развёртывание: GitHub → Railway (всё внутри Railway)

1. Код уже в этом репозитории на GitHub.
2. На [railway.app](https://railway.app): **New Project → Deploy from GitHub repo** → выбрать этот репозиторий.
3. Добавить базу: в проекте нажать **+ Create → Database → Add PostgreSQL**. База создастся тут же, рядом с приложением.
4. Связать приложение с базой (чтобы появилась `DATABASE_URL`):
   - Открыть сервис приложения → **Variables** → **New Variable** → **Add Reference** → выбрать `DATABASE_URL` из Postgres.
   - (Либо вручную: имя `DATABASE_URL`, значение `${{Postgres.DATABASE_URL}}`.)
5. Там же в **Variables** добавить остальное: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`, и данные МойСклад.
6. **Deploy**. Railway соберёт Node.js (Nixpacks), запустит `npm start` (см. `railway.json`), таблица `items` создастся сама. Публичный URL — это сайт.

Обновления: пушишь в GitHub → Railway пересобирает автоматически.

## Настройка Telegram-бота

1. В [@BotFather](https://t.me/BotFather): `/newbot` → задать имя → получить **токен**.
2. Вписать токен в Railway как `TELEGRAM_BOT_TOKEN`.
3. Узнать свой chat_id у [@userinfobot](https://t.me/userinfobot) (для группы — добавь бота в группу и посмотри ID).
4. Вписать его как `TELEGRAM_CHAT_ID`.
5. Redeploy. Напиши боту `/start`.

Команды бота:

| Команда | Действие |
|---------|----------|
| `/help` | список команд |
| `/list` | все товары (первые 50) |
| `/find АРТИКУЛ` | найти товар и его место |
| `/add АРТИКУЛ Название` | добавить товар |
| `/del АРТИКУЛ` | удалить товар |
| `/count` | количество товаров |
| `/export` | выгрузить весь список файлом (CSV для Excel) |
| `/ostatki АРТИКУЛ` | остаток по данным МойСклад |
| `/stats` | статистика бота: сколько пользователей, из какого магазина, сколько запросов |
| `/fixcompound` | найти в Овире и разбить все ранее сохранённые слитые артикулы (например «405638-BLBK-LGW» → 2 товара) на том же месте |

Уведомления в чат `TELEGRAM_CHAT_ID` приходят автоматически при добавлении, изменении, удалении и импорте товаров через сайт.

> Команды выше (кроме `/start`/`/help`/`/menu`) доступны только администратору (`TELEGRAM_CHAT_ID`/`TELEGRAM_ADMINS`).
> Обычные сотрудники используют бота через кнопки меню — их использование тоже считается, но статистика (`/stats`) видна только администратору в самом Telegram. На сайте (без пароля) этих данных нет.

### Поиск остатков в боте — три режима (кнопки меню)

- **🔎 Найти остаток (МойСклад)** — только по своему магазину (по умолчанию).
- **🌍 Остаток по всем складам** — по каждому найденному товару показывает остаток на **каждом**
  складе отдельно плюс итого, а не только в своём магазине. Доступно всем, не только админу.
- **📦 Найти на складе (где лежит)** — где физически стоит товар (этаж/ряд/ячейка) по локальной базе.

### Массовая расстановка по складу Овир

Админ может переслать боту (или напечатать) сообщение вида:

```
Ряд 8 Б
310197-CRL
310561-BKLD
405039-SLNV-BKCC
```

Слово «Ряд» можно не писать — если первая строка блока состоит ровно из числа и буквы
(например просто «8 Б»), бот тоже это поймёт как заголовок.

Бот сам определит этаж по букве ячейки (схема склада Овир: этаж 2 — буквы А Б Д Е З И Л М,
этаж 1 — буквы В Г Ё Ж Й К Н О) и проставит всем перечисленным артикулам склад Овир, этаж, ряд
и ячейку. Новые товары создаются автоматически (название берётся из каталога МойСклад, если
артикул там найден), уже существующие — переносятся на это место, даже если были на другом
складе. В одном сообщении можно прислать сразу несколько блоков «Ряд N Буква», а строки-комментарии
вперемешку с артикулами бот просто пропускает.

Если после номера модели идёт 2 и больше цветов через дефис (например `405638-BLBK-LGW` или
`310197-WHT-BBK-LAV-LTPK`) — это всегда несколько разных товаров одной модели, слитых вместе,
а не один товар с составным названием цвета. Бот разбивает такой код на отдельные артикулы
(`405638-BLBK` + `405638-LGW`, и т.д.) безусловно, не сверяясь с каталогом МойСклад — там эти
цвета часто не значатся отдельными позициями, хотя на полке это разные товары.

Если списки присылались ещё до того, как заработало это разбиение (или до какого-то из
исправлений формата), в базе могли остаться неразбитые слитые артикулы. Команда `/fixcompound`
сама найдёт все такие позиции в Овире и разобьёт каждую на отдельные товары на том же месте —
не нужно вручную искать и пересылать заново по одному.

## Интеграция с МойСклад (остатки)

Используется [JSON API 1.2](https://dev.moysklad.ru/doc/api/remap/1.2/). Запрос идёт на
`/entity/assortment?filter=article=АРТИКУЛ` — возвращает остаток, резерв, ожидание и доступное количество.

**Способ 1 — токен (рекомендуется):**
1. Получить токен (Basic-авторизацией логином/паролем МойСклад):
   ```bash
   curl -X POST https://api.moysklad.ru/api/remap/1.2/security/token -u ЛОГИН:ПАРОЛЬ
   ```
   В ответе будет `access_token`.
2. Вписать его в Railway как `MOYSKLAD_TOKEN`.

**Способ 2 — логин и пароль:**
- Задать `MOYSKLAD_LOGIN` и `MOYSKLAD_PASSWORD` в Railway (без токена).

Проверка: напиши боту `/ostatki АРТИКУЛ` или открой `https://<твой-railway-url>/api/stock/АРТИКУЛ`.

> Артикулы в приложении и в МойСклад должны совпадать. Если связывать нужно по коду, а не артикулу — поставь `MOYSKLAD_MATCH_FIELD=code`.

Полная синхронизация каталога (все модели, цвета, размеры, раскладка по складам) идёт в памяти
сервера и обновляется каждые 20 минут. Чтобы данные не пропадали на несколько минут при каждом
деплое (Railway перезапускает процесс — память очищается), последний успешный снимок каталога
сохраняется в Postgres (таблица `ms_cache`) и подхватывается сразу при старте — сайт и бот
показывают его, пока в фоне идёт свежая пересинхронизация.

## API (для сайта)

| Метод | Путь | Действие |
|-------|------|----------|
| GET | `/api/items` | все товары |
| POST | `/api/items` | добавить (`article`, `name`, `warehouse`, `floor`, `row`, `cell`) |
| PATCH | `/api/items/:article` | обновить |
| DELETE | `/api/items/:article` | удалить один |
| DELETE | `/api/items` | удалить все |
| POST | `/api/items/import` | импорт массива `items` |
| GET | `/api/stock/:article` | остаток из МойСклад |

## Локальный запуск (для отладки)

```bash
npm install
DATABASE_URL="postgres://user:pass@localhost:5432/sklad" \
TELEGRAM_BOT_TOKEN="..." \
TELEGRAM_CHAT_ID="..." \
npm start
```

## Тесты

Автотесты (`node --test`) проверяют разбор данных МойСклад (артикул/модель/цвет/размер/цена,
переименование складов) и синтаксис `server.js` и `public/index.html` — без обращения к
Postgres или МойСклад, поэтому работают и локально, и в CI, и на сборке Railway.

```bash
npm test
```

Запускаются автоматически:
- **При каждом деплое на Railway** — тесты прописаны как `npm run build`, Nixpacks выполняет
  их на этапе сборки. Если тест падает — сборка падает, и Railway не выкатывает сломанный код.
- **При каждом push/PR на GitHub** — workflow `.github/workflows/test.yml`.
